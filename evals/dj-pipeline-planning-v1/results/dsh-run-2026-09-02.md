### Remaining correctness problems

1. **Export is broken for timestamp-like input fields.** HuggingFace inferred `crawl_time` as a Python `datetime`. The local UTF-8 JSONL writer recursively converts dict/list/numpy/pyarrow values but returns `datetime` unchanged, after which `json.dumps` fails. This is an exporter implementation bug, not a missing cleaning operator. The existing serialization helper should handle `datetime`/`date`/`time` with an agreed ISO-8601 policy.
2. **Good-sample retention fails.** The language filter reduced 12 records to 7, while every downstream quality filter removed zero. Deduplication then reduced 7 to 5. Because both duplicate pairs must have survived for dedup to remove two records, one of the five intended clean/HTML articles was necessarily removed by the language filter. The five final stats lengths (`110, 99, 95, 123, 90`) indicate that the likely false negative is `TRM-005`; good-sample retention is therefore 4/5 = 0.80, below A3's required 0.95.
3. **Rule attribution is wrong.** `TRM-006` (short), `TRM-008` (symbols), and `TRM-009` (repetition) were consumed upstream by `language_id_score_filter`. Consequently the length, special-character, and repetition filters each reported no removals. Even though bad records disappeared, the pipeline cannot truthfully attribute them to the intended rules.
4. **Header/comment removal is only partial.** `clean_html_mapper` removes markup but retains visible `header`, `nav`, `footer`, and comment text. Thus A1's header-residual requirement is not satisfied by the selected built-in recipe.
5. **The 80-character rule is only approximated.** `text_length_filter(min_len=80)` counts total characters, not Chinese characters specifically.
6. **No structured stage-count report was delivered.** Counts exist in execution logs, but export failed, no run `report.md` exists, and the plan has no reporting postprocess. A5 is therefore not satisfied as an output artifact.
7. **The remaining stats artifact is not auditable by record.** `processed_stats.jsonl` has five rows containing only `__dj__stats__`; it omits `id` and `source_url`, so it cannot establish which source records survived.
8. **Deduplication is over-broad.** `document_deduplicator(ignore_non_character=True)` is useful for `TRM-003`/`TRM-012`, but can also merge documents that differ only in numbers or punctuation, potentially destroying factual distinctions.
9. **External capability resolution is unavailable.** `resolve_capabilities` returned `CAPABILITY_CONTROL_NOT_CONFIGURED`. This does not block native operators, but it means missing article-body extraction/reporting capabilities cannot be filled from a governed reusable catalog.

### Test-case/oracle assessment

The current `reachable / medium` oracle is not supported by the actual run. The case's gold candidates include `remove_header_mapper` and `remove_comments_mapper`; both are registered DJ operators, but their actual semantics are LaTeX/TeX header and `%`-comment removal rather than HTML `header/nav/footer` or webpage-comment removal. In the DSH search, the combined HTML-boilerplate requirement used `top_k=3`, returning `extract_tables_from_html_mapper`, `clean_html_mapper`, and `document_line_deduplicator`; `remove_comments_mapper` ranked fifth in a diagnostic `top_k=5` replay and `remove_header_mapper` ranked lower. Neither would change the supplied HTML fixtures, as verified with a minimal invocation. The case also requires a structured stage-count report that the recipe did not produce. The defensible choices are:

- relabel this case as mixed/unreachable and explicitly record article-body extraction plus structured reporting as gaps; or
- narrow the prompt to native `clean_html_mapper` semantics, define stage counts as log evidence, relax Chinese-character count to total text length, and recalibrate/reorder the language filter against the fixture.

Final evaluation: **Fail as executed, and oracle mismatch as designed.** The export bug must be fixed before any corpus result can be delivered, but fixing export alone will not resolve the retention, attribution, boilerplate-removal, and reporting failures.
